POPO 通过 Windows 上的 DJ01Bot TypeScript 桥接程序接入 Multica，复用共享会话与任务引擎。Windows 进程持有 POPO 连接，用工作区限定的通道凭证连 Multica。

一个 dj01bot 机器人对应一个 Multica 智能体。`robot_id` 取自本机 `~/.dj01bot/config.json` 的 `websocketRobots[].id`，默认是 `default`。

## 开始之前

- 工作区 owner 或 admin 在 Multica 创建一次性配对码。
- Windows 上已安装 DJ01Bot TypeScript 版本和 Node.js 22.5 或更新版本。在 DJ01Bot 根目录执行 `npm --prefix ts ci` 和 `npm --prefix ts run build`。
- 自托管需设置 `MULTICA_POPO_ENABLED=true`。

<Callout type="info">
`multica popo gateway` 已移除，改用 `node ts/dist/multica-bridge.js`。
</Callout>

## 1. 配对 Windows 通道

1. 在 Multica 创建一次性配对码（owner/admin）。
2. 在 Windows 的 DJ01Bot 根目录运行：

```bash
node ts/dist/multica-bridge.js pair --server https://your-multica.example --pairing-code <code>
node ts/dist/multica-bridge.js run --server https://your-multica.example
```

配对成功后把 `{server, bridge_id, token, workspace_id}` 写到 `%USERPROFILE%/.dj01bot/multica-bridge/`。保持 `run` 运行，心跳超过 45 秒会显示离线。

## 2. 把机器人连到智能体

1. 打开 **智能体**，选一个智能体，进入 **集成**。
2. 选择在线的 Windows 通道，以及空闲机器人（已连接且未被 dj01bot/Sparse 占用）。
3. 点击 **连接**。

一个机器人只能绑定一个有效的 Multica 智能体。

## 首次使用与账号绑定

成员第一次找机器人说话时，会收到一次性绑定链接（`/popo/bind?token=`）。打开、登录同一工作区，再回到 POPO 重发消息。链接 15 分钟过期。

## 怎么用

### 私聊

直接发文字，不需要 @。

### 群聊

在群里 @ 机器人发起请求。引用已关联任务的回复可以继续评论同一条任务。媒体附件和 Windows 扫码开通也有对应的桥接流程。

运行开始后，Multica 的任务卡片显示进度和最终状态。桥接程序收到消息时不会添加 "处理中" 贴纸；接收成功不代表任务已经开始。

### 命令

- `/new`、`/clear` 走共享引擎，和飞书一样。
- `/issue <标题>` 建 Multica 单（`origin_type=popo_chat`）。
- `/reply 任务编号 <评论>`、`/status 任务编号` 和 `/stop 任务编号` 操作已有任务。停止运行与任务状态分别记录。
- `/yixiezuo preview <工单链接>` 读取单张易协作工单。在本机以发送者绑定的同一个 Multica 成员账号运行 `multica yixiezuo bridge --workspace-id <工作区 UUID>`。
- `/yixiezuo show <操作 ID>` 查看来源材料或处理结果。
- `/yixiezuo import <工单链接> [--project <项目 UUID>]` 直接导入一张易协作工单。本机桥读完后机器人会回报成功或失败；任务保持未分配，不会自动开跑智能体。重复导入保留已有任务和已建立的通知路由。
- `/yixiezuo import <预览 ID> --confirm --project <项目 UUID>` 在预览确认后再导入。
- `/yixiezuo refresh 任务编号` 刷新来源快照，保留本地任务字段。
- `/yixiezuo publish 任务编号 [--status <来源状态>]` 的下一行填写结果与验证证据，先生成待复核内容；再发送 `/yixiezuo confirm <复核 ID>` 排队回写。确认在 15 分钟内有效，绑定同一成员、机器人、聊天、任务版本和来源快照。

导入时所选项目可以关联 `perforce_depot` 资源。成员分配任务后，运行会收到该项目的 P4 上下文。任务评论和运行结果回到原聊天；向易协作回写结果仍需单独确认。

## 个人会话模式与需求命令

新账号绑定默认普通聊天。升级前已绑定且机器人配置了需求模板的账号，保留原需求入口默认行为，直到成员显式选择模式。每位成员在每个私聊或群聊中独立选择模式。机器人模板只提供需求的默认来源模板。群聊中的模型上下文按 Multica 成员分开，自动附加的群历史不会进入个人上下文；明确引用或转发的内容仍作为输入，发到群里的消息与回复仍在群里可见。个人模式控制与需求查询私发给操作人，并注明原群聊。

| 命令 | 行为 |
| --- | --- |
| `/mode`、`/help` | 查看你的模式或命令帮助 |
| `/mode chat`、`/chat` | 切换普通聊天 |
| `/mode requirement`、`/requirement` | 切换需求流程，显示当前选择的需求 |
| `/requirement new [模板链接] <想法>` | 新建独立需求草稿 |
| `/requirement status [需求 ID]` | 查询需求阶段和下一步 |
| `/requirement list` | 列出你在此智能体下参与的近期需求 |
| `/requirement open <需求 ID>` | 选择有权访问的需求，返回 Chat 或任务链接 |
| `/requirement resolve <操作 ID> <新单链接>` | 回读并核对结果不明的来源草稿 |

`/new [消息]` 按你的当前模式新建普通 Chat 或独立需求；`/clear` 用于清空普通 Chat 的上下文。`/issue`、`/reply`、`/status`、`/stop` 与 `/yixiezuo` 保留各自行为，不会被需求入口吞掉。

需求入口需要该成员自己的易协作 bridge。澄清与批准在 Multica Chat 中进行；批准后沿用唯一任务执行和返工，最后人工验收。Multica 在会话列表和标题显示需求标识，并展示当前阶段及下一步。需求 Chat 按参与者角色授权，执行任务仍沿用工作区任务权限。

## 管理连接

**设置 → 集成 → POPO** 可查看通道和机器人。每位成员可以查看自己在各机器人下的 POPO 绑定、打开私聊绑定指引或解除绑定。解绑保留 Chat 和需求历史，但清除该机器人的个人模式选择。owner / admin 可以立即撤销通道凭证。断开机器人后该智能体不再收发 POPO，Multica 会话会保留。

## 自托管

```dotenv
MULTICA_POPO_ENABLED=true
```

未设置或不是 `true` 时，管理接口返回 `configured: false`，Windows 通道接口返回 `503 popo_not_configured`。

`popo-cli` 是登录用户身份（给别的 Windows 工具用），不是这条机器人通道。
