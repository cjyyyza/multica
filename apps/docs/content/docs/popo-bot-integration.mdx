POPO uses the same product surface as Feishu/Lark (IM channel + shared engine). A Windows process holds the POPO connection and talks to Multica over a workspace-scoped bridge token. The API server never opens POPO, popo-cli, or dj01bot.

One dj01bot robot maps to one Multica agent. Use a stable `robot_id` from `~/.dj01bot/config.json` (`websocketRobots[].id`), or `default`.

## Before you start

- A workspace owner or admin mints a pairing code in Multica.
- This Windows machine already runs a working dj01bot (`start.bat` / `dj01bot gateway`).
- Self-hosted servers set `MULTICA_POPO_ENABLED=true`.

<Callout type="info">
The Go command `multica popo gateway` is gone. Use `python -m nanobot.multica_bridge`.
</Callout>

## 1. Pair the Windows bridge

1. In Multica, create a one-time pairing code (workspace owner/admin).
2. On Windows:

```bash
python -m nanobot.multica_bridge pair --server https://your-multica.example --pairing-code <code>
python -m nanobot.multica_bridge run --server https://your-multica.example
```

Pairing writes `{server, bridge_id, token, workspace_id}` under `%LOCALAPPDATA%/dj01bot/multica-bridge/`. Keep `run` going so heartbeats stay fresh (45s without a heartbeat is offline).

## 2. Connect a robot to an agent

1. Open **Agents**, select an agent, then **Integrations**.
2. Choose an online Windows bridge and an idle robot (`connected` and not occupied by dj01bot/Sparse).
3. Click **Connect**.

A robot can belong to only one live Multica agent.

## First use and account binding

The first time a member messages the robot, it sends a single-use Multica account-binding link (`/popo/bind?token=`). Open it, sign in to the same workspace, then send the message again. The link expires after 15 minutes.

## Use the robot

### Private chats

Send text directly. No @-mention is required.

### Groups

Group @, media, QR onboarding, and `/reply` `/status` `/stop` are not in this version.

### Commands

- `/new` and `/clear` use the shared engine, same as Feishu.
- `/issue <title>` creates a Multica issue (`origin_type=popo_chat`).

## Manage connections

**Settings → Integrations → POPO** lists bridges and robots. Owners and admins can revoke a bridge token immediately. Disconnecting a robot stops inbound/outbound for that agent but keeps Multica conversations.

## Self-hosting setup

```dotenv
MULTICA_POPO_ENABLED=true
```

Unset or any value other than `true` hides the management APIs (`configured: false`) and returns `503 popo_not_configured` on the Windows bridge routes.

`popo-cli` is a logged-in user identity used by other Windows tools. It is not this robot channel.
