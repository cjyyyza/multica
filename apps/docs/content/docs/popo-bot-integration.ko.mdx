POPO는 Windows의 DJ01Bot TypeScript 브리지를 통해 Multica의 공유 대화 및 태스크 엔진에 연결합니다. Windows 프로세스가 POPO 연결을 유지하며 워크스페이스 범위의 자격 증명을 사용합니다.

자세한 절차는 [영문](/popo-bot-integration)과 [중문](/zh/popo-bot-integration)을 보세요.

1. Multica에서 일회용 페어링 코드를 만듭니다(owner/admin).
2. Node.js 22.5 이상을 설치하고 DJ01Bot 루트에서 `npm --prefix ts ci`와 `npm --prefix ts run build`를 실행합니다. 이후 `node ts/dist/multica-bridge.js pair`와 `run`을 실행합니다. 인자는 상세 절차를 참고하세요.
3. 온라인 Windows 브리지와 유휴 로봇을 에이전트에 연결합니다.

서버 스위치는 `MULTICA_POPO_ENABLED=true`입니다. `multica popo gateway`는 제거되었습니다.

기존 태스크는 `/reply`, `/status`, `/stop`으로 관리합니다. `/yixiezuo preview`와 `show`로 내용을 검토한 뒤 `import --confirm`으로 미배정 태스크를 생성합니다. `publish`는 검토 내용을 만들며, 같은 멤버가 같은 채팅에서 `confirm`해야 결과 반영이 대기열에 등록됩니다. 검토는 15분 후 만료되고 태스크나 원본이 변경되면 다시 검토해야 합니다.

## 개인 대화 모드

새 계정 연결의 기본 모드는 일반 채팅입니다. 요구사항 템플릿이 설정된 로봇에 기존에 연결된 계정은 참여자가 모드를 명시적으로 선택할 때까지 기존 요구사항 입력 기본값을 유지합니다. 같은 로봇을 사용해도 각 참여자는 개인 채팅과 그룹별로 `/mode chat` 또는 `/mode requirement`를 독립적으로 선택합니다. 그룹의 모델 기록도 발신자별로 분리되지만 그룹에 게시한 메시지는 계속 공유됩니다.

`/requirement help`는 도움말, `list`는 참여 중인 요구사항, `status [요구사항 ID]`는 단계 조회, `open <요구사항 ID>`는 선택, `new [템플릿 URL] <아이디어>`는 독립 요구사항 생성입니다. 개인 명령의 결과는 발신자에게 비공개로 전달합니다. 명확화, 승인 및 검수는 Multica에서 진행합니다.

**설정 → 통합 → POPO**에서 각 참여자는 자신의 계정 연결을 확인하고 개인 채팅 연결 안내를 열거나 연결을 해제할 수 있습니다. 해제 후에도 Chat과 요구사항 기록은 유지되지만 해당 로봇의 개인 모드 선택은 지워집니다.
