# 易协作 PM 单向同步与任务单分诊

`multica yixiezuo pm-sync` 每次执行一轮：读取易协作未完成 BUG，更新 Multica，并逐单通知任务单分诊员。它可以使用运行中的 PM agent 的工作区任务身份；保留现有单张预览、导入、刷新和人工确认回写流程。

PM 命令的易协作调用仅限查询目录、用户、工单列表和单单详情。它不会领取本机桥接队列，也不会调用来源更新、评论、流转或发布接口。服务端只接收来源数据，在 Multica 内执行写入，不访问易协作。

## 配置与运行

源电脑安装并登录 `popo-cli`。构建并部署同一版本的服务端和 CLI，通过受管环境应用迁移。分诊员绑定可用运行时，实际 `max_concurrent_tasks` 必须为 `1`；调用权限使用现有调用者身份规则，不借用其他成员账号。

迁移 `9009` 对旧导入表的变更是幂等的。如旧环境缺少 `yixiezuo_import`，先恢复原有单张导入表及索引，再执行 `9009` 中的幂等 DDL；已记录的条件跳过迁移不会因再次运行 `migrate up` 自动重放。

用 `multica project list --output json` 取得目标项目 UUID；用 `multica workspace member list --output json` 核对成员，映射时使用 `user_id`，不是成员关系行的 `id`。

保存 UTF-8 `pm-sync.json`，将下面的项目占位符替换成真实 UUID。配置文件不包含任何凭证：

```json
{
  "source_host": "dj01.pm.netease.com",
  "source_project": "dj01",
  "assignee_emails": [
    "zengrui01@corp.netease.com",
    "zhououxiang@corp.netease.com"
  ],
  "issue_type": "BUG",
  "project_id": "<Multica 项目 UUID>",
  "triage_mention": "[@任务单分诊员](mention://agent/ee6f11fb-44c2-4226-a01d-1b0ba9921651)"
}
```

`source_project` 等于实例前缀 `dj01` 时，扫描该实例可访问的项目。也可以填写源项目数字 ID 或目录中的完整项目名来缩小范围。`BUG` 同时匹配实际目录里的 `BUG-…` 子类型；其他类型按完整名称匹配。项目、人员、类型和状态的过滤值均从当前目录解析，不硬编码来源人员或状态 ID。

未完成查询严格排除 `已关闭 / 已取消 / 已解决 / 交付测试`。DJ01 还存在名为 `关闭` 的状态，它不在上述名单中；本轮按原配置包含它，并在报告中提示人工确认，不自行将它当作 `已关闭`。

```text
multica yixiezuo pm-sync --workspace-id <工作区 UUID> --config-file pm-sync.json
multica yixiezuo pm-sync --workspace-id <工作区 UUID> --config-file pm-sync.json --output json --timeout 30m
```

默认输出中文 Markdown，每轮包含扫描时间、范围和单数、新增同步、更新、未分类转交、异常与待人工确认。无变化写“本轮无变化”。读取、写入或触发失败会保留单号和错误，命令以非零状态退出；PM agent 仍应把完整报告作为本轮结果交付。网络返回不确定时不盲目重试，下一轮按来源键重新查重。

## 幂等与字段更新

- 正式导入记录以工作区、来源实例和外部单号去重。旧单先匹配描述中独立一行的 `外部单号：<id>`，再匹配目标项目与规范化标题。多条匹配、冲突的来源链接或已有不同来源关联均报告待人工确认。
- 匹配旧单、补标记、更新字段和保存来源关联在同一事务中完成。描述使用数据库锁内读到的最新正文，只补缺失的外部单号标记，不重写人工正文。
- 新单写入原标题、来源链接、外部单号、来源状态和原始优先级，初始为 `backlog`。优先级缺失时用 `none`，未知值不覆盖已有本地优先级，并明确报告。
- 人员先按明确的 `assignee_map` 映射，再按工作区成员邮箱精确匹配；缺少邮箱时只接受唯一的完整名称匹配。映射不到成员的新单保持未分配，报告来源负责人。首次纳管旧单时保留已有本地负责人，只为未分配单填入成功映射的成员。可选映射格式为 `"assignee_map": {"来源邮箱": "Multica 成员 user_id"}`。
- 后续只应用发生变化的来源字段，不用未变化的来源标题、优先级和负责人反复覆盖本地调整。将 `source_project` 从实例前缀改为项目 ID 或完整名称时沿用已有同步基线。新成员加入或映射配置变化可以填补空负责人；分诊员已完成的本地分类和分配不会因来源字段未变化而被撤销。
- 对账清单在任何写入前完整读取。以前已同步、但不再出现在“未完成”查询中的单会单独读回；只有读到 `已关闭` 或 `已取消` 才将本地未完成单置为 `done` 或 `cancelled`，并原子记录依据评论。不把查询缺席、读取失败、`已解决` 或 `交付测试` 推断成关闭。
- 已绑定的本地单被删除时明确失败并要求人工确认，不自动重建。成员可以通过单张预览和显式导入重新创建该单，成功后用新关联替换删除记录。来源读取的时间或版本过旧时拒绝写入。

## 未分类转交

默认候选必须同时满足：无标签、无负责人，且处于 `backlog`、真实 Triage，或描述包含“待分诊”。若工作区使用自定义“类别”属性，配置 `category_property_id` 为其真实 UUID，此时按该属性为空筛选，不以标签代替类别。已完成单和已有人工编辑、人工评论的单跳过；创建动作和 PM 自动同步不算人工处理。

候选清单先完整扫描，再串行逐单发送一条评论。评论照抄 `triage_mention` 的 label 和 UUID，附标题、状态、优先级摘要。PM 不给分诊员分配同步工作，也不代替它分类、认领或改派。

每个工作区任务对每个分诊员保留一条持久通知记录。成功的 `queued`、`coalesced`、`deferred` 回执视为已通知，后续周期跳过重复；这表示输入已交付，不表示分类已完成。触发失败记录 `invocation_not_allowed`、`target_unavailable` 等实际原因，其他有调用权限的发起人也可以重试，复用原评论并保留原作者和调用归属；重试时重新检查当前发起人与原评论的调用权限。分诊员并发数不为 `1` 时，在新增评论前返回 `triage_concurrency_must_be_one`。进程在触发后中断时，下一轮检查该评论已有的任务，不重复启动。评论被删除时要求人工确认。

## PM agent 指令

每次唤醒执行一次上述 `pm-sync` 命令，把 stdout 报告作为本轮结果交付；非零退出也交付报告。不要另行创建来源工单，不调用 `publish`、`confirm`、`bridge` 或来源写工具，不另发重复分诊评论。周期调度使用现有任务唤醒机制，配置文件和运行时的来源访问权限需先准备好。

## 验证边界

数据库测试覆盖同单并发重跑、旧单接管、人工正文和本地分配保护、负责人映射、明确关闭依据、删除与旧读取拒绝、分诊失败重试和并发去重。CLI 测试使用模拟来源及 API；驱动测试采用当前接口形状并检查写工具在进入子进程前被拒绝。接口 schema 测试拒绝缺失身份的成功回执和畸形扫描结果。

2026-10-14 的本地验证：相关 Go 回归（数据库、完整路由、幂等与权限）以及报告输入保护测试、core 类型检查与字段 lint、8 个接口 schema 测试、11 个现有单张导入及人工确认界面测试、服务端/CLI/迁移工具构建均通过。迁移 `9009` 和 `9010` 已在本 checkout 的受管数据库应用，SQLC 已重新生成。

真实只读驱动检查解析了 DJ01 目录和筛选值，分页发现 760 张工单，并独立读回工单 `8099` 的详情；来源优先级为空，按“缺失”记录。可显式重跑该来源检查：

这些测试没有创建生产任务或执行真实分诊员。完整生产周期、服务部署和实际 agent 执行尚未验证。
