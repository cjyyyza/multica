# 易协作单张工单导入

易协作是任务来源。用户选择一张工单、预览材料并确认后，Multica 创建一条未分配的原生任务；之后由用户选择成员或智能体，在现有看板中推进。来源更新不会自动改写本地任务。

结合 DJ01Bot 与 P4 管理 UE 项目时，参见 [完整工作流](./ue-p4-popo-yixiezuo-workflow.md)。机器人可以发起相同的操作，导入和回写仍需显式确认。

## 使用流程

1. 使用本分支构建的服务端、CLI 和 web/desktop；通过受管环境应用数据库迁移。
2. 在能访问易协作、已登录 `popo-cli` 的电脑上，以相同的 Multica 账号、工作区运行 `multica yixiezuo bridge --workspace-id <workspace-uuid>`。
3. 在任务页点击“从易协作导入”，或进入“设置 → 集成 → 易协作”。粘贴单张工单的 HTTPS 链接，点击“读取预览”。
4. 核对正文、业务字段、评论、附件和来源状态，选择 Multica 项目，再确认导入。
5. 在任务中分配成员或智能体。导入本身不分配、不启动执行。重复导入同一工作区、实例、工单时，打开已有任务并保留本地修改。
6. 验收后，在任务详情的易协作区域填写结果、验证证据及可选的来源状态，勾选复核确认后回写。

CLI 也提供同一流程：

```text
multica yixiezuo preview https://<instance>.pm.netease.com/issues/<id>
multica yixiezuo import https://<instance>.pm.netease.com/issues/<id> --confirm --project-id <project-uuid>
multica yixiezuo bridge --once
```

`preview` 只读易协作并输出材料；`import` 不带 `--confirm` 时同样只输出预览。界面预览会将附件暂存到 Multica，确认导入时与任务一起关联。单文件上限 20 MB，总计 80 MB，超限或缺失材料会明确失败。界面展示最多最近 100 条历史记录中的评论；存在更早记录时显示提示并保留原单链接。

## 同步边界

- 没有全量看板拉取、定时状态覆盖、自动建易协作工单或自动回写。
- 本机桥接只领取当前账号、工作区明确排队的操作。服务端不执行本机命令，也不访问易协作。
- 看板卡片显示来源编号和处理状态；任务详情提供原单链接、来源状态、材料、附件及逐次操作错误。卡片共用一个轻量查询，不逐卡读取完整材料。刷新来源只更新来源快照，不替换本地标题、描述、状态或负责人。
- 回写仅追加用户确认的结果评论，并可修改明确选择的来源状态。不会提交标题、描述、优先级、日期或负责人。
- 新状态来自该工单的 `getIssueFieldOptions`，不使用硬编码中文状态映射。
- 确认时绑定用户查看的本地 revision 和来源摘要；来源预览在确认期间发生变化时拒绝提交。回写前再次检查来源摘要，更新时携带 `getIssueForm` 返回的 `lock_version`，随后读回评论标记与状态。并发冲突、权限导致字段未应用、网络结果不确定均不会显示为成功。
- 回执记录实际提交的 Multica revision；提交后产生的新修改继续显示为待复核。批量编辑及后台修改同样通过 revision 判定，不依赖单条编辑入口的标记。
- 操作持久化在数据库中，使用领取令牌限制迟到回执。桥接中断后的外部写入不会自动重试；结果不确定时先刷新、检查原单，再由用户决定后续动作。相同回执可以重试且不会再次修改易协作。

## 易协作接口

通过 `popo-cli pmmcp` 调用 `get_issue_base`、`getIssueForm`、`get_issue_journals`、`get_issue_attachments`、`get_attachment_download_info`、`getIssueFieldOptions`，以及仅用于明确回写的 `update_issue`。正文内嵌截图需要额外提取，不能仅依赖附件列表。

## 验证

- 驱动测试覆盖来源身份、北京时间、内嵌截图、材料摘要、未知状态拒绝、并发冲突、最小写入字段、读回及重复回执。
- CLI 测试使用测试创建的可执行文件和模拟 Multica API，不访问真实账号。
- 数据库测试覆盖预览不创建任务、重复导入、未分配且不启动 Agent、显式确认，以及旧回执不吞掉新版本。需受管 PostgreSQL 环境运行。
- UI 测试覆盖读取与确认导入分离、打开已有任务和集成入口。发布界面要求显式验收确认。
